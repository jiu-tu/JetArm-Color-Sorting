## 阶段一：功能落地（mode=right 与模式参数）

### patch1 — 新增 mode:=right，右侧固定关节角放置

- **问题**：只有一个按色标点放置的路径；验收功能一（任意物块放右侧指定区）无法实现。
- **修改**：
  1. 中央区约束去掉 y 下界（`0.25w<x<0.75w and y>0.2h` → 仅 `0.25w<x<0.75w`），绿色积木（center_y≈76）放行；
  2. 新增 `self.mode` 参数（默认 `color`）；
  3. 放置分支：`mode=right` 用固定关节角序列（J1=125）放右侧；`mode=color` 走原色标点逻辑。

### patch2 — 中央区收紧 + 连续跳过 40 帧强制切色 + 退出保护

- **问题**：色标板红色块（x≈150~160）面积大于红积木，最大轮廓常落在色标板；跳过日志刷屏；`main finally` 的 `destroy_node` 偶发崩溃。
- **修改**：
  1. 中央区收紧为 `x∈[0.3w, 0.7w]`，把色标板排除在检测区之外；
  2. 新增 `skip_count`：连续 40 帧跳过即强制切换目标颜色；
  3. 跳过日志限频（每 20 帧打一次）；
  4. `destroy_node / rclpy.shutdown` 加 try 保护。

### patch3 — 伺服跟踪加深度门槛 0.15~0.5m

- **问题**：机械臂对背景 / 远处干扰（人、墙面）跟踪乱抓。
- **修改**：跟踪前取目标 5×5 邻域深度中位数，不在 0.15~0.5m 范围按跳过处理（计数 + 40 帧切色），机械臂保持静止。

### patch3_1 — 深度门槛适配积木摆放在 10~20cm

- **问题**：三色积木摆在正前方 10~20cm，0.15m 下界把目标全挡掉。
- **修改**：伺服深度门槛下限 0.15→0.08；主循环距离超限下限 0.1→0.06。

### patch4 — 摄像头基准角 4 号舵机 60°→25°

- **问题**：积木摆正前方 10~20cm，60° 视角视野过高，摄像头看不到近处物块。
- **修改**：所有基准位姿 `(4, 60)` → `(4, 25)`（≥6 处）。

### patch5 — 深度上限 0.5→0.35m

- **问题**：远处背景（色标板 / 背景绿）仍会触发误检。
- **修改**：伺服深度门槛上限与主循环距离上限统一收紧到 0.35m。

### patch6 — 回退 4 号舵机 25°→60°

- **问题**：**25° 时手眼标定矩阵失效**（矩阵按 60° 标定），抓取全面乱抓；同时 10~20cm 过近导致逆解出界。
- **修改**：全部回退为 `(4, 60)`；**积木摆放距离改为 25~33cm**。这是本项目第一个关键取舍：*标定一致性 > 视角近场覆盖*。

## 阶段二：抗干扰与稳定性（跟踪侧）

### patch_track8 — ColorTracker 排除画面上方（y<0.35h）

- **问题**：色标板红块 (128, 62) 与背景绿 (319, 161) 位于画面上方，面积大于积木（红积木 2919px² vs 色标红块 5822px²），最大轮廓恒中色标板。
- **修改**：`ColorTracker.proc` 中对每个候选轮廓加 `if (center_y*2) < 0.35*h: continue`，只认积木区（积木实测 y=305~399）。
- **效果**：**三大技术死结之一解决**。

### patch7 — 中央区按实测积木位置放宽

- **问题**：实测积木（60° 视角）位于 red(395,305) green(498,339) blue(602,399)，色标板 red(128,62)+左下(36,429)，背景绿(319,161)；0.3w~0.7w 把蓝积木(602)都挡掉。
- **修改**：中央区放宽为 `x∈[0.25w, 0.95w] 且 y∈[0.45h, 0.95h]`（按 640×480 折算 x∈[160,608]、y∈[216,456]）。

### fix_patch2 — 修复 patch2 误伤 + 补跳过段计数切色

- **问题**：patch2 的字符串替换误伤了 `pick` 内 `out_count` 重置段的缩进；跳过段补丁未完全生效。
- **修改**：修复拆行损坏的 `out_count` 段；为 0.3 约束跳过段补上计数切色逻辑。

### 深度图尺寸修正（对话实测记录，非补丁）

- **问题**：深度图实际约 640×400（非 640×480），patch7 的 y 上界 0.95h≈380 会把积木 y=389~400 全部误拦。
- **修改**：中央区只保留 y 下界 `0.40h < center_y`，不再设上界。
- **效果**：**三大技术死结之二解决**。

## 阶段三：悬停标定与坐标补偿（核心量化调试）

### patch9 — hover 悬停标定模式

- **问题**：抓取误差 5~6cm 无法定位来源（视觉 / 手眼矩阵 / 逆解 / 舵机？）。
- **修改**：新增 `-p hover:=true` 模式：检测到目标后**只悬停于其上方 6cm、不闭爪**，保存 `/tmp/hover.jpg`、打印 `pose_t` 后退出——把"抓取"拆成"定位"与"夹取"两步，逐环节排除误差来源。

### 悬停标定第①轮 — 偏远 5~6cm、偏左 2~3cm

- **实测**：期望 (0.282, 0.128, 0.07)，夹爪中心与积木偏差 5~6cm（远）、2~3cm（左）。
- **修改**（patch10）：`x: +0.025 → -0.030`（TCP→夹爪中心 x 偏移约 2.2~2.5cm，标定发现需改为靠近方向）；新增 `y: -0.025`。

### 悬停标定第②轮 — 姿势异常

- **实测**：(0.128, 0.07, −0.012)，姿态异常。
- **处理**：回中修复，重新标定。

### 悬停标定第③轮 — 偏近 3cm

- **实测**：(0.127, 0.048, −0.012)，用户反馈机械臂偏近 3cm。
- **修改**（patch11）：`x: -0.030 → 0.000`。

### 悬停标定第④轮 — 偏近 3cm、偏右 2cm；z 反投影为负

- **实测**：(0.166, 0.052, −0.011)。
- **修改**（patch12）：`x: 0.000 → +0.030`（往远）；`y: -0.025 → -0.045`（往左）；`z: +0.010 → +0.050`（抬高 5cm，根治 z 反投影为负导致的"抓深"）。
- **追加**：hover 分支打印**实际末端位姿** `HOVER actual`，验证 pose_t 是否被真实执行。

### 悬停标定第⑤轮 — 期望与实际一致

- **实测**：(0.185, 0.029, 0.022)，`HOVER pose_t` 与 `HOVER actual` 一致。
- **结论**：**坐标变换链本身无误，剩余偏差来自深度反投影环节**——进入逐色补偿阶段。

## 阶段四：逐色补偿与放置偏移（验收定稿）

- **问题**：不同颜色积木形状/反光不同，统一补偿后单色仍有残余偏差。
- **定稿**（对话实测微调，坐标语义：x 正=远、y 正=左、z 正=升）：

| 颜色 | 抓取补偿 (x, y, z) | 放置偏移（远+ / 左+） |
| --- | --- | --- |
| 红 | (+0.050, −0.004, +0.020) | 远 +1.5cm，左 +3.5cm |
| 蓝 | (+0.040, −0.005, +0.030) | 远 +1.5cm |
| 绿 | ( 0.000, −0.015, +0.020) | 远 +1.5cm |

- **效果**：抓取误差 5~6cm → <1cm；三色分拣连续验收通过（见 README 实验结果表）。

## 关键经验

1. **手眼标定一致性 > 视角优化**：4 号舵机角度必须与标定时的 60° 一致，25° 视角虽近但标定失效，得不偿失。
2. **深度图真实尺寸要先实测**：标称 640×480 与实际 640×400 导致按比例算的过滤边界整段失效。
3. **最大轮廓 ≠ 目标**：色标板/背景比目标大时，必须用区域过滤（画面上方排除 + 中央区）而非只比面积。
4. **悬停标定把"定位"和"夹取"解耦**：先证明坐标变换链正确，再把剩余误差归因到具体环节，避免盲调。
5. **逐色补偿**：形状/反光差异导致统一补偿不可用，按颜色分表维护。
