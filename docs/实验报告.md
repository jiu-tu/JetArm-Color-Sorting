五、实验原理

5.1 颜色空间与图像分割原理

RGB颜色空间对光照变化敏感，而LAB颜色空间将亮度（L通道）与颜色（a、b通道）分离，颜色检测更稳定。本系统将相机采集的RGB图像转换为LAB空间，针对红、绿、蓝三种目标颜色设置各自的下限与上限阈值，通过inRange函数进行二值化，得到只包含目标颜色区域的掩膜图像。对掩膜图像使用findContours提取轮廓，对每个轮廓计算其面积，选取面积最大的轮廓作为目标，并使用minEnclosingCircle得到最小外接圆，圆心即为目标物块的中心像素坐标。

5.1.1 官方参考方案的HSV颜色检测

官方样例采用HSV颜色空间进行颜色检测，其核心代码如下（摘自官方get_Sqaure函数）：

```python

# 官方HSV颜色识别代码（get_Sqaure）
(lowerb, upperb) = color_hsv
mask = self.image.copy()
hsv = cv.cvtColor(self.image, cv.COLOR_BGR2HSV)      # 转到HSV空间
img = cv.inRange(hsv, lowerb, upperb)                # 阈值筛选
mask[img == 0] = [0, 0, 0]                           # 非掩码区置黑
kernel = cv.getStructuringElement(cv.MORPH_RECT, (5, 5))
dst_img = cv.morphologyEx(mask, cv.MORPH_CLOSE, kernel)   # 形态学闭运算
dst_img = cv.cvtColor(dst_img, cv.COLOR_RGB2GRAY)
ret, binary = cv.threshold(dst_img, 10, 255, cv.THRESH_BINARY)  # 二值化
contours, heriachy = cv.findContours(binary, cv.RETR_EXTERNAL, cv.CHAIN_APPROX_SIMPLE)
for i, cnt in enumerate(contours):
    x, y, w, h = cv.boundingRect(cnt)                # 外接矩形
    area = cv.contourArea(cnt)
    if area > 1000:                                  # 面积过滤
        point_x = float(x + w / 2)                   # 矩形中心
        point_y = float(y + h / 2)
        (a, b) = (round(((point_x - 320) / 4000), 5), round(((480 - point_y) / 3000) * 0.8 + 0.19, 5))
```

官方HSV方案的处理流程为：BGR转HSV→inRange阈值分割→形态学闭运算（填充孔洞）→转灰度→二值化→轮廓提取→boundingRect外接矩形→面积过滤（>1000像素²）→计算中心点→代入像素映射公式。其中闭运算（MORPH_CLOSE）用于弥合目标内部的细小空洞和断裂，使轮廓更完整。

5.1.2 本系统采用LAB颜色空间的原因

对比官方HSV方案，本系统选用LAB颜色空间，主要考虑如下：

（1）光照鲁棒性：LAB空间将亮度信息完全放在L通道，颜色信息集中在a、b通道；而HSV空间中V（明度）与颜色通道仍存在耦合，光照变化时阈值需要频繁调整。实验环境中桌面灯光、窗外光线变化明显，LAB分割在实验中表现出更好的稳定性；

（2）分割一致性：经实测，同一积木在不同时刻的LAB阈值区间稳定，而HSV区间受V通道波动影响较大；

（3）本系统处理的是红、绿、蓝三色积木，颜色饱和度高，LAB阈值只需设置6个参数（L、a、b各自下限与上限），参数空间小、易调。

5.2 深度相机与深度测量原理

Orbbec Gemini深度相机基于结构光或双目视差原理，输出与RGB图像对齐的深度图，每个像素的灰度值表示该点到相机平面的距离（单位：毫米）。本系统在目标中心附近取3×3或5×5像素窗口，对窗口内有效深度值取平均值（或中位数）作为目标物块的实测距离，以提高抗噪能力。深度图分辨率与RGB图分辨率不同（实测深度图约为640×400），因此在做坐标对应时必须分别获取两图的分辨率，不能直接假设二者尺寸一致。

5.2.1 官方方案的平面透视变换

官方样例在检测前先对图像进行透视变换归一化：通过摄像头提取十字标定板轮廓，用机器视觉方法提取轮廓的四个角点，将标定板框内平面透视变换为矩形平面，消除摄像头安装角度引起的透视畸变。其核心代码如下：

```python

# 官方透视变换代码（calibration_map + Perspective_transform）
dp = []
h, w = self.image.shape[:2]
contours = self.Morphological_processing()          # 形态学处理取轮廓
for i, c in enumerate(contours):
    area = cv.contourArea(c)
    if low_bound < area < high_bound:               # 面积范围限制
        mm = cv.moments(c)                          # 图像矩
        if mm['m00'] == 0: continue
        cx = mm['m10'] / mm['m00']                # 质心
        cy = mm['m01'] / mm['m00']
        dp = np.squeeze(cv.approxPolyDP(c, 100, True))  # 多边形逼近取四角点
# 按图像四分区分四角点(左上/左下/右下/右上)
# 原图四点 pts1 -> 变换后矩形 pts2 = [[0,0],[0,480],[640,480],[640,0]]
M = cv.getPerspectiveTransform(pts1, pts2)
Transform_img = cv.warpPerspective(image, M, (640, 480))
```

官方形态学处理流程为：转灰度→高斯滤波（5×5核）→二值化（阈值130）→3×3核开运算（iterations=4或8）→RETR_EXTERNAL提取外轮廓。开运算（MORPH_OPEN）用于去除图像中的细小噪点，先腐蚀后膨胀。

5.2.2 本系统的深度测量方案

本系统使用Orbbec Gemini深度相机，深度图每个像素值表示该点到相机平面的距离（毫米）。官方方案仅能获得平面上的二维坐标，本系统则利用深度信息获得目标的三维坐标。为提高深度测量抗噪能力，本系统在目标中心附近取3×3窗口，对窗口内满足0<depth<10000mm的有效像素取均值作为实测距离；窗口法可以抑制深度图在物体边缘的跳变噪声。实测过程中还发现深度图分辨率约为640×400，与RGB图640×480不同，因此在做像素对应时必须分别获取两图的分辨率，这一细节是本系统调试中一个重要发现。

5.3 像素坐标到世界坐标的变换

已知相机内参矩阵K（由CameraInfo话题获得），目标中心像素坐标为(u, v)，实测深度为d，则目标在相机坐标系下的坐标为：

5.3.1 官方2D像素映射公式

官方样例不依赖深度信息，直接使用经验映射公式将像素坐标转换为工作平面坐标（官方get_Sqaure与get_pos函数）：

```python

# 官方像素坐标->位置公式
(a, b) = (round(((point_x - 320) / 4000), 5),
           round(((480 - point_y) / 3000) * 0.8 + 0.19, 5))
# 其中 point_x, point_y 为像素坐标；a 为x方向(单位米)，b 为y方向
# 请求逆解时：request.tar_x = a;  request.tar_y = b + self.offset
```

该公式本质上是将640×480图像中心(320,240)作为机械臂工作平面的原点，通过经验系数4000与3000将像素差映射为米，0.19为相机到工作平面的基准高度经验值。该方案成立的前提是：目标始终位于同一水平工作平面、且相机安装角度固定，即"固定平面假设"。

5.3.2 本系统3D反投影方案的原理

本系统利用深度相机内参K（焦距fx、fy与主点cx、cy，由ROS2的CameraInfo话题获取）与实测深度d进行三维反投影：

```python

X_c = (u - cx) × d / fx
Y_c = (v - cy) × d / fy
Z_c = d   （单位：米）
```

得到相机坐标系下的坐标后，依次经手眼标定矩阵H（相机在机械臂末端的安装位姿，本系统使用官方提供的hand2cam_tf_matrix）变换到机械臂末端坐标系，再经末端位姿矩阵E（由正运动学服务获得）变换到机械臂基坐标系：

```python

P_world = E × H × P_camera
```

相比官方2D公式，3D反投影不依赖固定平面假设：即使积木高度不同（如积木堆叠），深度信息也能给出正确的z坐标。但3D反投影对相机内参、手眼矩阵的精度敏感，这正是不加补偿时出现厘米级误差的原因，也是本系统开展悬停标定与补偿修正的出发点。

X_c = (u - cx) × d / fx ， Y_c = (v - cy) × d / fy ， Z_c = d

其中fx、fy为焦距，cx、cy为主点坐标。在代码中通过depth_pixel_to_camera函数实现。得到相机系坐标后，利用手眼标定矩阵H（相机在机械臂末端的安装位姿）将坐标变换到机械臂末端坐标系，再结合机械臂末端在基坐标系下的位姿矩阵E（通过正运动学服务获取），最终得到物块在机械臂基坐标系下的世界坐标：

P_world = E × H × P_camera

5.4 机械臂运动学与舵机控制原理

机械臂具有6个自由度（1号云台、2/3/4号机体、5号腕关节、10号夹爪）。系统通过ROS2服务向运动学解算服务发送目标位置(x, y, z)与姿态角，服务端调用逆运动学求解器（libdofbot_kinemarics库）返回各关节的目标角度，再将角度转换为舵机脉宽值，通过串口总线发布到舵机控制器。舵机采用脉宽位置控制，例如1号舵机中位为500，夹爪舵机（10号）600为闭合、200为张开。


当kin_name为"fk"（正运动学）时，只需提供当前六个关节角，服务端调用dofbot_getFK返回末端坐标与姿态；当kin_name为"ik"（逆运动学）时，只需提供目标坐标与姿态，服务端返回六个关节目标角度。本系统的set_pose_target服务请求正是基于该协议构造。

5.4.2 官方逆解越界修正

官方在得到逆解结果后，增加了越界修正逻辑：当3号关节角出现负值（越界）时，将其超出的角度按比例分配到1号与4号关节，保证机械臂姿态可达：

```python

# 官方逆解越界修正代码
if joints[2] < 0:
    joints[1] += joints[2] * 3 / 5
    joints[3] += joints[2] * 3 / 5
    joints[2] = 0
```

该修正基于机械臂的冗余自由度：3号关节负角度不可达时，通过调整2号与4号关节的等效组合逼近目标位置。本系统在调试中也遇到过类似情况（目标位置过近导致逆解异常），参考该思路通过调整目标位置与姿态角规避。

5.5 色标板自动标定原理

颜色分拣功能需要将积木放到左侧对应颜色的色标区域。系统启动时，程序对左侧色标板进行扫描：对色标板图像中的红、绿、蓝三个色块分别进行颜色检测与中心定位，通过上述坐标变换反投影得到各色标区在机械臂基坐标系下的三维坐标，并连续采集10帧取中位数，作为该颜色的放置点place_points。该过程实现了放置位置的自动标定，避免了人工测量。

5.5.1 官方offset.txt手工误差校准机制

官方《机械臂应用开发指南》附录A.1专门指出："机械臂在完成相机校准后精准抓取色块仍有误差"。原因在于：商家在生产机械臂时，难免由于规格问题导致每台机械臂硬件误差不同。官方的解决方案是在程序中手工校准，将校准参数写入配置文件config/offset.txt，由两个浮点型参数组成：

```python

# 官方offset.txt校准方法（摘自指南附录A.1）
# 1) 机械臂抓取略微靠后(色块后方) -> 适当加大该参数
#    例如从 0.008 修正到 0.01
# 2) 机械臂抓取略靠前(色块前方)   -> 适当减少该参数
#    例如从 0.008 修正到 0.006
# 使用方式: request.tar_y = posxy[1] + self.offset
```

官方的校准只修正了y方向一个参数，且为全局单一参数。本系统的悬停标定与逐色补偿正是对该思想的深化：不仅补偿y方向，还独立补偿x、y、z三个方向，且针对红、绿、蓝三种颜色分别设置参数，解决了单参数无法适应视场不同区域误差不一致的问题。

6.2 视觉检测算法实现

视觉检测核心代码（LAB空间阈值分割与轮廓提取）如下：

```python

# RGB -> LAB 二值化，提取目标颜色
lab = cv2.cvtColor(rgb_image, cv2.COLOR_RGB2LAB)
mask = cv2.inRange(lab, lowerb, upperb)   # 阈值由启动参数 lab_data 给出
# 提取轮廓，选面积最大者
contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
min_c = None
for c in contours:
    (center_x, center_y), radius = cv2.minEnclosingCircle(c)
    if (center_y * 2) < 0.35 * h:        # 排除画面上方的色标板/背景
        continue
    if min_c is None or abs(cv2.contourArea(c)) > min_c[2]:
        min_c = (center_x, center_y, abs(cv2.contourArea(c)))
# 中央区过滤：只抓正前方区域（避免误抓背景）
if not (0.25 * w < center_x < 0.95 * w and 0.40 * h < center_y):
    continue
```

官方样例的抓取动作由move()函数实现，采用"架起—到位—下降—夹紧—架起—转位—放下—张开"的序列，每步通过Arm_serial_servo_write6_array下发六个关节角度与动作时长（毫秒）：


本系统的动作序列在原理上与官方一致，但做了两点改进：一是抓取前先以高位（目标上方6cm）到达，再分两次下发关节角完成下降，避免一次到位时夹爪与积木碰撞；二是增加"抬升6cm再抓稳"的中间步骤，即闭爪后抬升一段距离再重新定位，确保积木被抓牢后再进入放置流程。官方以固定关节角序列（如joints_down=[45,50,20,60,265,...]）实现到各色区的放置，本系统功能一（定位夹取）沿用了这一思路（右侧指定区使用固定关节角序列），功能二（颜色分拣）则升级为色标坐标反投影+逐色偏移的自动标定方案。

6.6 程序总体架构设计

本系统的程序采用"父类+子类"结构，代码分为两层：

（1）父类track_and_grab.py：封装公共能力，包括ColorTracker颜色追踪类（LAB阈值分割、轮廓筛选、中心返回）、深度图与RGB图的同步读取、手眼标定矩阵hand2cam_tf_matrix、逆解服务客户端（set_pose_target）、抓取动作函数pick()以及主循环main()；

（2）子类sort_grab.py：实现分拣业务逻辑，包括色标板放置点自动标定、两种分拣模式（mode=right/mode=color）、中央区约束、深度门槛、逐色补偿参数以及悬停标定模式（hover）。

主循环main()的每帧处理流程为：读取RGB图与深度图→LAB阈值分割→轮廓筛选与最小外接圆→中央区约束过滤→3×3窗口深度均值→深度门槛判断→目标稳定判断（相邻帧偏差小于2且连续5帧取均值）→像素反投影→手眼/末端变换→逐色补偿→启动线程执行pick()抓放。将pick()放入独立线程，避免动作执行期间阻塞图像处理循环，保证系统可连续跟踪。

6.8 悬停标定模式的实现原理

针对抓取误差难以定位来源的问题，本系统设计了悬停标定模式（hover:=true）。其原理为：将"检测定位"与"抓取执行"两个环节解耦——检测到积木后，机械臂只运动到目标正上方约6cm处悬停，不闭合夹爪，同时保存当前画面截图并打印目标坐标pose_t与实际末端位姿HOVER actual，随后程序退出。通过对比pose_t与HOVER actual，可以直接判断坐标变换是否正确；通过观察截图，可以判断悬停位置相对于积木的偏差方向与大小。

该模式的核心代码如下：

```python

# 悬停标定模式核心逻辑（hover:=true）
if self.hover:
    msg = set_pose_target(position, yaw, [-180.0, 180.0], 1.0)
    res = self.send_request(self.set_pose_target_client, msg)
    if res.pulse:
        set_servo_position(self.joints_pub, 1, ((1, res.pulse[0]),))
        time.sleep(1)
        set_servo_position(self.joints_pub, 1.5, ((1, res.pulse[0]), (2, res.pulse[1]),
                                                 (3, res.pulse[2]), (4, res.pulse[3]), (5, res.pulse[4])))
        time.sleep(1.5)
    # 获取实际末端位姿并打印对比
    self.get_endpoint()
    self.get_logger().info("HOVER actual: " + str(self.endpoint[:3, 3]))
    self.get_logger().info("pose_t      : " + str(pose_t))
    cv2.imwrite("hover.png", result_image)   # 保存悬停画面
    self.running = False                      # 悬停后退出，等待人工观察
```

五轮悬停实测数据已在前文表7-1给出。悬停标定的关键结论：第五轮实测HOVER actual与pose_t完全一致，证明set_pose_target执行精确，偏差完全来自反投影坐标（手眼矩阵/相机内参残差），只能通过补偿修正；同时发现z坐标反投影恒为负值，即相机系z方向与世界系z方向存在系统性偏差，这是抓取过深、夹爪触桌的根源，必须增加z方向补偿。

```python
中央区x范围	[0.3w, 0.7w]	[0.25w, 0.95w]	按实测积木像素位置放宽（red x=395等）
```

七、实验过程描述

7.1 摄像头视角与手眼标定问题排查

实验初期，机械臂以4号舵机60°的基准姿态停靠时，相机画面中无法看到摆放在正前方的积木（画面被人体和平板设备遮挡），导致系统无法检测到目标。为此尝试将4号舵机下调至25°、20°、15°、10°等角度，虽然画面中能看到操作平面上的积木，但此时手眼标定矩阵失效——该矩阵是按4号=60°姿态标定的，改变关节角后相机与末端的相对位姿发生变化，导致坐标变换错误，机械臂出现"乱抓"现象。最终将4号舵机恢复至60°基准姿态，并请实验人员将积木摆放在相机视野可及的正前方区域（实测距离约25~33cm），问题解决。

7.2 色标板干扰导致的误识别排查

颜色分拣功能调试中，程序一直检测到画面左上方的色标板红色块（像素坐标约(128,62)），而不是正前方的红色积木。分析发现色标板红色块轮廓面积（约5822像素²）大于红色积木（约2919像素²），而程序选取面积最大的轮廓，因此必然命中色标板。解决方案分两步：一是在ColorTracker.proc中增加"若轮廓中心纵坐标的二倍小于0.35倍图像高度则跳过"的过滤，将位于画面上方的色标板与背景绿色物体排除；二是在主循环中央区约束中设置0.25w<x<0.95w、0.40h<y，只保留画面下方积木区域。修改后实测积木像素坐标red(395,305)、green(498,339)、blue(602,399)均能正确被识别。

7.3 深度图尺寸不一致导致的全部误拦

在设置中央区约束时，最初使用"0.25w<x<0.95w且y<0.95h"的写法，期望排除画面上方。但实测深度图分辨率约为640×400而非640×480，0.95h≈380，而积木实测纵坐标y=389、400，均大于380，导致所有积木都被判定为"非中央区"而不抓取。修改为只设置下界"0.40h<center_y"并保留x范围后，识别恢复正常。该问题说明坐标过滤必须基于实际图像分辨率，不能想当然。

7.4 悬停标定与逐轮补偿微调

由于手眼标定残差和机械臂硬件误差，反投影得到的世界坐标与夹爪实际位置存在厘米级偏差。为此在程序中加入hover悬停标定模式：检测到积木后只移动到积木正上方6cm处悬停，不闭爪，同时保存截图并打印目标坐标pose_t与实际末端位姿，用于分析偏差来源。

经过五轮悬停实测（详细数据如下），发现：set_pose_target执行非常精确（第五轮实测HOVER actual与pose_t完全一致），偏差完全来自反投影坐标本身，因此只能通过补偿参数修正。同时在悬停过程中发现z坐标反投影恒为负值，这是机械臂抓取过深、夹爪触桌的根源，需要增加z方向补偿抬高。

| --- | --- | --- | --- |
| 悬停① | [0.282, 0.128, 0.07] | 偏远5~6cm、偏左2~3cm | x-0.030, y-0.025 |
| 悬停② | [0.128, 0.07, -0.012] | 姿势异常（未回中起跑） | 回中脚本修复 |
| 悬停③ | [0.127, 0.048, -0.012] | 偏近3cm | x回0.000 |
| 悬停④ | [0.166, 0.052, -0.011] | 偏近3cm、偏右2cm | x+0.030, y-0.045, z+0.050 |
| 悬停⑤ | [0.185, 0.029, 0.022] | actual与pose_t一致 | 确认偏差在反投影，转逐轮微调 |

7.5 逐轮实测微调与最终参数收敛

在悬停标定基础上，通过"抓取—观察—微调"的迭代方式对红、绿、蓝三种颜色分别进行补偿微调。以红色为例，先后经过y补偿-0.040→-0.020→-0.017→-0.015→-0.012→-0.009→-0.004的多轮调整，最终红色抓取补偿为x+0.050、y-0.004、z+0.020；放置偏移在远方向+3.5cm→+2.5cm、左方向+4cm~+8cm之间多轮调整，最终确定为远+0.015m、左+0.035m叠加在色标点上。蓝色抓取补偿经过y在-0.005~-0.040之间反复调整，最终收敛为x+0.040、y-0.005、z+0.030；绿色因体积较小、识别略不稳定，仅调整x=0.000、y-0.015、z+0.020。通过坐标系约定（x正=远离机械臂，y正=机械臂左侧，z正=升高）保证了每轮调整方向判断的正确性。

九、结果分析

9.1 功能完成度分析

实验完成了课程设计要求的两个基本应用功能：定位夹取（功能一）与颜色分拣（功能二）。颜色分拣模式下红、绿、蓝三种颜色积木均实现了完整抓放流程；定位夹取模式下物块均成功放置到右侧指定区。两个功能均满足"识别机械臂正前方区域物块"的要求，实现了从视觉检测到机械臂动作的完整闭环。

9.2 精度分析

实验实测抓取距离集中在0.27~0.33m范围内，与官方指南推荐的25~35cm抓取窗口一致。经过悬停标定与逐轮补偿后，夹爪中心与积木中心的对齐误差从最初的5~6cm收敛到1cm以内，放置落点误差在2~3cm以内，满足演示要求。误差来源主要包括：

（1）手眼标定残差：相机与机械臂末端的变换矩阵由官方标定获得，但实际安装存在毫米级偏差；

（2）深度测量噪声：深度图在物体边缘存在跳变，窗口均值法虽能抗噪但仍引入小量误差；

（3）机械臂硬件误差：各舵机实际转角与理论值存在微小偏差，且随负载变化；

（4）放置动作的关节角序列为固定值，未根据物块大小自适应调整。

9.3 误差修正方法分析

本系统采用"悬停标定+逐轮实测微调"的方法修正坐标误差：首先通过hover模式让机械臂悬停在目标正上方，对比目标坐标与实际末端位姿，确定偏差方向与大小；再通过多轮"抓取—观察—微调"迭代，逐步收敛各颜色补偿参数。该方法简单有效，避免了重新进行手眼标定的复杂流程，且补偿参数按颜色分别存储，适应了不同位置物块的差异性。该思路与华为官方指南附录A"机械臂在完成相机校准后精准抓取色块仍有误差"一节提出的硬件误差手工校准方法一致。

9.4 与官方误差处理方案的对比分析

官方指南附录A.1明确承认"机械臂在完成相机校准后精准抓取色块仍有误差"，并给出offset.txt手工校准方案：抓取靠后加大参数（0.008→0.01），靠前减小参数（0.008→0.006）。本系统的补偿体系与该方案一脉相承，但进行了三点深化：

（1）维度扩展：官方只修正y方向单一参数，本系统独立补偿x、y、z三个方向。悬停标定发现z方向反投影恒为负的系统性偏差，若不单独补偿z，夹爪必然过深触桌；

（2）按颜色细分：不同颜色的积木在视场中的位置不同，而相机畸变与手眼矩阵残差随视场位置变化，官方单一参数无法适应。本系统为红、绿、蓝分别标定补偿参数，红色最终为x+0.050/y-0.004/z+0.020，蓝色为x+0.040/y-0.005/z+0.030，绿色为x0.000/y-0.015/z+0.020，参数差异印证了细分必要性；

（3）标定流程自动化：官方offset.txt靠人工反复试抓调整，本系统通过悬停模式先量化偏差方向与大小，再针对性调整，减少了盲目试错轮次。

这一对比也验证了本系统误差修正方法的设计合理性：与官方"承认误差存在—手工校准"的思路一致，但更具系统性和数据支撑。

十、实验过程遇到的问题与解决方案

10.1 问题一：SSH远程连接偶发中断

现象：调试过程中SSH连接偶发报错"Network error: Software caused connection abort"，会话断开。

解决：断开后重新连接即可恢复；同时将系统休眠相关服务屏蔽（systemctl mask sleep.target等），避免休眠导致断连。调试过程中还发现板载系统在长时间运行后偶发资源占用，通过重启相关节点解决。

10.2 问题二：摄像头角度与手眼标定冲突

现象：为看到正前方积木将4号舵机从60°下调至25°后，机械臂出现乱抓，无法准确定位。

分析：手眼标定矩阵是按4号=60°的基准姿态标定的，改变关节角后相机与末端的相对位姿改变，矩阵失效。

解决：将4号舵机恢复至60°基准姿态，积木摆放在正前方25~35cm的可视范围内，系统恢复正常。

10.3 问题三：色标板干扰抢选目标

现象：颜色分拣时程序一直锁定画面左上方的色标板红色块，不识别正前方红色积木。

分析：色标板红块轮廓面积（5822像素²）大于红色积木（2919像素²），而检测算法选取面积最大的轮廓。

解决：在轮廓筛选环节增加"中心纵坐标二倍小于0.35倍图像高度则跳过"的过滤，排除画面上方区域；同时中央区约束只保留画面下方积木区域。修改后积木均能正确识别。

10.4 问题四：深度图分辨率与RGB不一致导致误拦

现象：设置中央区约束后所有积木都被判为"非中央区"，完全不抓取。

分析：中央区约束使用"y<0.95h"写法，但深度图实际分辨率约640×400而非640×480，0.95h≈380，而积木纵坐标实测y=389~400，全部超过阈值被误拦。

解决：改用只设置下界"0.40h<center_y"、保留x∈[0.25w,0.95w]的约束，识别恢复正常。

10.5 问题五：抓取过深、夹爪触桌

现象：机械臂抓取时夹爪下降过深，多次触碰桌面或压住积木，导致抓取失败。

分析：悬停标定发现z坐标反投影恒为负值，说明相机系z方向与世界系z方向存在系统性偏差。

解决：增加z方向补偿（红色+0.020、蓝色+0.030、绿色+0.020），并调整放置松开高度为离地约4cm，问题解决。

10.6 问题六：各颜色积木误差方向不一致

现象：相同补偿参数下，红色积木定位准确而绿色积木偏差较大，且绿色积木体积较小、识别不稳定。

分析：不同颜色积木摆放位置不同，相机畸变与手眼标定残差在视场不同区域不一致，且绿色积木轮廓面积小、受光照影响大。

解决：采用按颜色分别设置补偿参数的方案，通过多轮实测独立收敛红、绿、蓝各自的抓取与放置补偿；对绿色单独开识别画面确认检测目标正确。

10.7 问题七：背景人体与设备导致"抬头乱抓"

现象：实验过程中机械臂多次对着正前方上方区域反复摆头，疑似在"乱抓"背景，没有抓取面前的积木。

分析：相机视野中除积木外，还存在实验人员手臂、支架上的平板设备等大块物体，其颜色或亮度特征在某些帧会误触发检测；同时目标丢失后程序切换颜色、重新搜索，机械臂会跟随误检目标运动，表现为"对着背景乱抓"。

解决：采取三级防护：①中央区约束（0.25w<x<0.95w且0.40h<y），只处理画面下方正前方区域；②深度门槛（0.06~0.35m），背景与人体距离通常超过0.5m被直接排除；③连续40帧无有效目标强制切换颜色，避免长时间锁定错误目标。三级过滤后，"抬头乱抓"现象消除，机械臂只在积木区域动作。

10.8 问题八：目标未稳定即触发抓取（"虚空一抓"）

现象：机械臂在目标中心仍在移动（跟踪未收敛）时就执行抓取，导致夹爪落空。

分析：跟踪过程中目标中心每帧都在变化，若偏差未收敛就触发pick()，抓取点计算基于抖动中的中心坐标，必然偏移。

解决：增加稳定判定——相邻两帧的pitch/yaw伺服偏差均小于2时，才开始累计中心坐标，连续5帧取均值作为最终抓取点；同时将pick()放入独立线程，动作期间继续跟踪，动作完成后再回到检测状态。稳定判定后"虚空一抓"明显减少，抓取点稳定性显著提升。

十四、拓展思考：横放长方体积木的直立放置方案

14.1 问题描述

本系统当前实现的功能为：识别机械臂正前方红、绿、蓝积木，抓取后放置到右侧指定区域或左侧对应颜色的色标区域。课程验收时，指导老师提出了一个拓展思考题：若将目标物块替换为横放在桌面上的小长方体积木（长轴水平），如何让机械臂在抓取后将其"立着"（长轴竖直）放置在对应区域？该问题考察的是机械臂末端姿态控制能力，是现有"定位夹取—平面放置"流程向"姿态调整—定向放置"升级的典型进阶场景。

14.2 难点分析

要完成"横抓竖放"，需要在现有系统上解决四个新问题：

（1）姿态检测难：现有程序通过minEnclosingCircle（最小外接圆）返回目标中心，只关心"目标在哪里"，不区分积木的长宽方向。横放的长方体积木必须先判断其长轴方向（即积木是横着摆的、长轴朝哪个角度），才能决定抓取时夹爪的开合方向，否则无法为后续翻转做准备；

（2）姿态变换难：现有抓取动作（pick函数）全程保持夹爪竖直朝下的姿态，只通过yaw绕竖直轴旋转。而"立着放"要求积木的长轴从水平变为竖直，本质是让末端绕水平轴旋转90°，现有流程没有这一环节，需要引入绕水平轴的翻转（roll或pitch）；

（3）夹持稳定性难：翻转过程中积木同时受重力与旋转惯性作用，若夹持点不在积木重心附近、或夹爪夹紧力不足，积木会在翻转中滑落或绕夹持点偏转，导致抓取失败；

（4）放置稳定性难：直立放置要求积木底端先接触台面、重心投影落在底面范围内，松爪时机与下降高度需精确配合；若积木重心偏高或夹持偏置，松爪后积木容易倾倒。

14.3 积木姿态检测方案

在视觉检测环节，将原minEnclosingCircle改为minAreaRect（最小外接矩形），可以同时获得矩形中心、宽高尺寸与旋转角度，据此判断积木是否横放并提取长轴方向：

```python

# 姿态检测：最小外接矩形提取长宽与角度
rect = cv2.minAreaRect(cnt)
(center_x, center_y), (w, h), angle = rect
long_axis  = h if h > w else w     # 长轴尺寸
short_axis = w if h > w else h     # 短轴尺寸
aspect = long_axis / short_axis    # 长宽比
if aspect > 1.3:                   # 判定为横放的长方体积木
    block_angle = angle            # 记录长轴相对图像坐标系的旋转角
    cv2.drawContours(result_image, cnt, -1, (0, 255, 0), 2)
    cv2.putText(result_image, 'block angle: %.1f' % angle, (10, 30),
                cv2.FONT_HERSHEY_PLAIN, 1.2, (0, 255, 0), 1)
```

实现上也可以先用boundingRect的宽高比（w与h）做粗判断，再对满足"横放"条件的轮廓调用minAreaRect精化角度。长宽比阈值（如1.3）可根据实测积木的尺寸比例调整；方形积木（长宽比接近1）不满足横放判定，保持原流程即可。

14.4 抓取姿态选择：夹爪开合方向与长轴平行

横放积木的长轴水平。若夹爪按原姿态抓取（夹爪开合方向与积木长轴垂直），积木在夹爪中呈"横梁"状态：夹爪只包住积木短边两侧的一小段，翻转时积木容易绕夹持点摆动甚至脱出。改进方法：抓取前将末端绕竖直轴旋转，使夹爪开合方向与积木长轴平行，即夹住积木长边面的两侧。此时夹持包络最大、接触面积最大、摩擦力最大，翻转时最稳定：

```python

# 抓取前调整yaw，使夹爪开合方向与积木长轴平行
# 夹爪开合方向与机械臂坐标系的y轴方向关联，
# 通过yaw叠加积木长轴角度进行补偿
grab_yaw = 30 + block_angle        # 原yaw=30基础上叠加长轴角
msg = set_pose_target(position, grab_yaw, [-180.0, 180.0], 1.0)
res = self.send_request(self.set_pose_target_client, msg)
```

注意：yaw方向（正负）与block_angle的对应关系需要通过一次悬停实测确定——若发现夹爪朝向与积木长轴平行但夹持在长边而非短边，说明方向取反，将grab_yaw改为30减去block_angle即可。

14.5 腕部翻转直立方案

积木从水平翻转为竖直，本质是末端绕水平轴旋转90°。本系统提供两种实现途径：

方案一：姿态角方案（推荐）。官方Kinemarics.srv服务协议完整支持roll、pitch、yaw三个目标姿态角，而本系统目前只使用了yaw。扩展set_pose_target请求，在翻转阶段传入roll=±90°，逆解服务即可自动解算出实现该末端姿态的五个关节角组合，由机械臂整体协同完成翻转。为避免积木在快速旋转中滑落，翻转分两步执行：先转45°并停顿，待积木在夹爪中稳定后再转到90°；翻转前先抬升6cm，防止翻转过程中积木碰触桌面：

```python

# 分步翻转：先抬升，再45°→90°两段旋转
flip_pos = position.copy()
flip_pos[2] += 0.06                 # 先抬升6cm再翻转
# 第一步：转到45°，停顿稳定
msg1 = set_pose_target(flip_pos, grab_yaw, [-180.0, 180.0], 1.0, roll=45)
res1 = self.send_request(self.set_pose_target_client, msg1)
if res1.pulse:
    set_servo_position(self.joints_pub, 1.5, ((1, res1.pulse[0]), (2, res1.pulse[1]),
                                             (3, res1.pulse[2]), (4, res1.pulse[3]), (5, res1.pulse[4])))
    time.sleep(1.5)
# 第二步：转到90°，积木长轴竖直
msg2 = set_pose_target(flip_pos, grab_yaw, [-180.0, 180.0], 1.0, roll=90)
res2 = self.send_request(self.set_pose_target_client, msg2)
if res2.pulse:
    set_servo_position(self.joints_pub, 1.5, ((1, res2.pulse[0]), (2, res2.pulse[1]),
                                             (3, res2.pulse[2]), (4, res2.pulse[3]), (5, res2.pulse[4])))
    time.sleep(1.5)
```

方案二：固定关节角方案。若使用的逆解服务版本不支持roll参数，可参照本系统mode=right功能放置动作的实现方式——夹取抬升后，直接下发一组经手工标定的固定关节角序列（例如同时调整4号、5号关节角度实现腕部翻转），再保持翻转后的姿态移动到放置区。该方案动作直观、便于逐步试调，但每改变一个翻转角度都需要重新标定关节角，通用性不如姿态角方案。

14.6 直立放置动作序列

翻转完成后，保持末端竖直姿态，按以下序列完成直立放置：

（1）移动：保持翻转后的姿态（夹爪水平、积木竖直），将积木移动到对应区域正上方；

（2）对位：缓慢下降至积木底端距台面约1~2cm处，可短暂松开夹爪再轻夹一次，利用重力让积木底面与台面大致平行；

（3）触面：继续缓慢下降，直至积木底端轻触台面（此时不宜再下降过多，防止压弯或顶翻积木）；

（4）松爪：张开夹爪（10号=200），保持末端不动约0.5s，观察积木是否站稳；

（5）撤离：确认积木直立稳定后，末端抬升离开放置区，回到基准姿态，进入下一次检测。

若积木因重心偏移在松爪后倾倒，可采取两项辅助措施：一是在放置区预置高度约1cm的定位挡板，松爪时积木底部倚靠挡板形成支撑；二是抓取时尽量使夹持点位于积木几何中心（重心）正上方，减小松爪瞬间的倾倒力矩。

14.7 方案要点总结

综上，"横抓竖放"的核心要点可以概括为五句话：

（1）姿态检测是前提：用minAreaRect长宽比判断横放，并提取长轴角度；

（2）抓取姿态决定稳定性：抓取时调整yaw使夹爪开合方向与积木长轴平行，最大化夹持包络与摩擦力；

（3）翻转遵循"先抬升、分步转、夹紧转"：先抬升6cm防止碰桌，45°停顿再转90°防止滑落，夹爪夹紧（10号=600）保证摩擦；

（4）放置遵循"贴面慢松"：底端轻触台面后再松爪，必要时用挡板辅助扶正；

（5）与三维分拣衔接：该能力可与本系统已有的三维形状分拣程序（shape_sort_grab.py，按轮廓圆度区分圆柱与长方体）相结合，形成"颜色+形状+姿态"的完整分拣方案，是本课题进一步升级的方向。
